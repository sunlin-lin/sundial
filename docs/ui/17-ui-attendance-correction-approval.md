# UI 與 Schema 設計：簽核／補打卡簽核

## 確認狀態

本文件內容已由使用者要求記錄，列為正式 UI、流程與 Schema 規劃；本文件較新的審核歷程設計覆蓋先前單次 `reviewed_* `欄位方案。

## 導覽與權限

```text
簽核
└─ 補打卡簽核
```

只有具備補打卡審核權限的角色可查看及操作。

## 預設查詢與分頁

- 進入頁面預設狀態為待審核，立即載入第 1 頁。
- 每頁固定 20 筆，顯示目前頁、總筆數、總頁數及換頁操作。
- 待審核依申請時間由舊到新，等待最久者優先。
- 年月預設當月，以補卡工作日期查詢。
- 可依狀態、部門、人員及補卡類型篩選。
- 條件變更回到第 1 頁；查詢、排序、分頁由後端處理。

部門顯示補卡日期當時的有效部門。第一版逐筆審核，不提供批次核准。

## 明細

顯示申請人、補卡日期／類型／時間／原因、當日班表、工作與休息時段、全部原始及有效／撤銷打卡、來源與大約地址。核准前預覽核准後上下班配對、工時、遲到、早退及缺勤；正式結果仍於核准後重算。

## 狀態操作

| 狀態   | 薪資尚未核算     | 薪資已開始核算 |
| ------ | ---------------- | -------------- |
| 待審核 | 查看、核准、退回 | 只可查看       |
| 已核准 | 查看、撤銷核准   | 只可查看       |
| 已退回 | 查看、撤銷退回   | 只可查看       |
| 已撤回 | 只可查看         | 只可查看       |

### 核准

核准前再次檢查申請仍待審核、未被員工撤回、該類型尚無有效打卡且薪資尚未核算。核准後建立來源為人工補登且無 GPS 的正式打卡，新增審核歷程並重算 `attendance_results`。

### 退回

原因必填；新增退回歷程，不建立打卡且不重算出勤。

### 撤銷核准

原因必填；保留原核准並新增撤銷歷程。核准時產生的人工補登打卡標記撤銷，不得 DELETE；重算出勤，申請回到待審核。

### 撤銷退回

原因必填；保留原退回並新增撤銷歷程。不涉及打卡或出勤重算，申請回到待審核。

## 薪資與併發限制

- 薪資開始核算後，補卡審核結果不得變更。
- 前端停用操作，後端仍須再次驗證。
- 出勤重算完成前不得開始薪資核算。
- 兩位審核者同時操作時，第一筆成功後，後送操作必須被拒絕並重新載入狀態。
- 員工已撤回的申請不得審核。

## `attendance_correction_reviews`

**資料表註釋：** 補打卡申請不可變的核准、退回與撤銷審核歷程。

| 欄位                               | 資料型態   | 必填性   | 欄位註釋                                 |
| ---------------------------------- | ---------- | -------- | ---------------------------------------- |
| `id`                               | `uuid`     | 必填     | PK                                       |
| `attendance_correction_request_id` | `uuid`     | 必填     | FK → `attendance_correction_requests.id` |
| `action_code`                      | `integer`  | 必填     | 核准、退回、撤銷核准或撤銷退回           |
| `action_by`                        | `uuid`     | 必填     | 操作者                                   |
| `action_at`                        | `datetime` | 必填     | 操作時間                                 |
| `reason`                           | `text`     | 條件必填 | 退回、撤銷核准及撤銷退回時必填           |
| `created_at`                       | `datetime` | 必填     | 建立時間                                 |

歷程只能新增，不可修改或刪除；申請主檔保存目前狀態。本表取代 `attendance_correction_requests.reviewed_by`、`reviewed_at`、`review_comment`。

## 正式打卡來源

`attendance_records` 增加：

| 欄位               | 資料型態  | 必填性 | 欄位註釋                                           |
| ------------------ | --------- | ------ | -------------------------------------------------- |
| `source_type_code` | `integer` | 必填   | 現場打卡、人工補登等來源類型                       |
| `source_id`        | `uuid`    | 選填   | 人工補登時指向 `attendance_correction_requests.id` |

核准產生的正式打卡必須可唯一追溯至補打卡申請，撤銷核准時據此撤銷正確事件。
