# UI 設計規劃：班別設定與排班模式

## 確認狀態

本文件內容已由使用者明確同意，列為正式功能規劃。

## 導覽結構

> 選單位置：`人事作業 → 班別設定`

班別設定定義「一天怎麼上班」，排班模式定義「哪一天套用哪個班別」。班別、排班規則、員工實際班表及後續異動必須分層管理。

## 班別設定

班別列表提供班別代碼或名稱、工作類型、跨日、彈性、狀態等條件，預設顯示啟用班別，每頁20筆。

列表顯示班別代碼、名稱、工作類型、工作時段、休息時段、應工作時數、跨日、彈性、狀態、使用狀況及操作。

新增或修改班別包含：

- 班別代碼、名稱、工作類型、說明及啟用狀態。
- 一段或多段工作時段。
- 一段或多段有薪／無薪休息時段。
- 跨日判定。
- 彈性及核心工時設定。
- 系統計算的應工作分鐘。

一般班、跨日班、分段班、中空班、有薪及無薪休息、彈性班、核心工時班、待命班及備勤班均納入整體規劃。

班別一旦被排班引用，會影響歷史班表及出勤判定。時間及工時規則不得直接覆蓋歷史；應停用舊班別並複製為新班別，或由後續版本化方案承接。

## 固定與循環排班

正式納入規劃的模式：

- 固定星期班。
- 每日不同固定班。
- 錯峰固定班。
- 固定跨日班。
- 壓縮工作週。
- 做二休二、做三休一、做四休二等任意天數循環。
- 日夜輪替。
- 兩班制、三班制。
- 按週輪班。
- 大小週及單雙週班表。

循環班不得綁死七天星期制；以週期長度、週期日內容及定位基準日展開。

## 班組排班

系統規劃支援A、B、C、D等班組使用同一套輪班規則但套用不同週期起點。

班組後續獨立設計需包含班組主檔、班組成員有效期間、班組主管、班組套用規則及週期定位。這些資料不得直接塞入班別主檔。

## 人工與非固定排班

納入：

- 每月人工逐日排班。
- 零工／非固定排班。
- 臨時叫班。
- 季節性排班。
- 專案期間排班。

零工沒有排班的日期不得判定為缺勤。臨時叫班及特殊安排必須建立正式日班表並留下原因與建立者。

## 班表異動

納入：

- 臨時調班。
- 特殊日期覆蓋。
- 公司停班。
- 員工換班。
- 代班。
- 待命被叫回。
- 備勤轉正式工作。

所有異動均保留原班表、新安排、原因、操作者及時間，不得刪除或覆蓋歷史。

## 員工換班

流程：

```text
員工提出換班
→ 選擇自己的班表及交換對象
→ 對方同意
→ 主管審核
→ 同時更新雙方班表
→ 保存雙方異動紀錄
```

規則：

- 兩筆班表均尚未開始。
- 對方拒絕後流程結束。
- 審核前申請人可撤回。
- 成功時必須同時更新兩人，不能只改一方。
- 更新前檢查工時、休息間隔及班表衝突。
- 已結算期間不得換班。

## 代班

原員工班表保留並關聯代班員工；代班員工同意及主管審核後，建立代班員工實際班表。

- 代班員工不得有重疊班表。
- 代班員工工時及加班依新班表計算。
- 原員工請假仍依原班表計算。
- 已結算期間不得新增或撤銷代班。

## 待命與備勤

待命安排和實際被叫回工作分開保存；備勤安排和轉為正式工作也分開保存。

待命／備勤需規劃日期、時段、方式或地點、實際通知／轉工作時間、實際工作起訖、打卡、工時及計薪結果。待命或備勤時間不得直接混入實際工作時間。

## 公司停班

保存原班表、停班日期或時段、原因、停班後日別、是否計薪、建立者及時間。公司停班不得直接刪除原班表。

## Schema 對應

既有Schema可承接固定星期、任意循環、兩班／三班、跨日、分段、人工排班、零工、臨時調班、季節性及專案期間：

- `shift_definitions`
- `shift_work_periods`
- `shift_breaks`
- `schedule_rules`
- `schedule_rule_details`
- `employee_schedule_assignments`
- `schedule_periods`
- `employee_schedules`
- `schedule_changes`

需獨立補充Schema責任但尚未定案正式表名：

- 彈性上班區間、核心工時及彈性下班計算。
- 班組及班組成員歷史。
- 換班申請、雙方確認、審核及雙班表關聯。
- 代班申請、同意、審核及原／代班表關聯。
- 公司停班事件及受影響班表。
- 待命／備勤安排及實際轉工作紀錄。

完整欄位與正式表名須在各流程逐一確認後，回寫 [班別、排班與出勤 Schema](../schema/03-scheduling-attendance.md)，不得由本UI文件自行定案。
