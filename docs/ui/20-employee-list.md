# 人事作業／員工清單 UI 定案

> 狀態：本輪已確認  
> 對應 Schema：主要回寫於 [公司、角色權限與組織](../schema/01-company-access-organization.md)、[組織人事、薪資與人事成本](../schema/02-employee-payroll-cost.md)及[系統稽核](../schema/05-regulatory-system.md)。

## 1. 選單與列表

左選單「人事作業」下設「員工清單」。預設顯示目前在職員工。

### 查詢條件

- 員工編號或姓名
- 部門
- 任職狀態
- 帳號狀態

### 列表欄位

| 欄位 | 說明 |
|---|---|
| 員工編號 | 公司內員工編號 |
| 姓名 | 員工姓名 |
| 部門 | 目前有效部門 |
| 職稱 | 目前有效職稱 |
| 僱用類型 | 目前有效任職資料 |
| 到職日 | 目前任職的到職日期 |
| 任職狀態 | 在職、離職等 |
| 帳號狀態 | 啟用或停用 |
| 操作 | 查看並進入修改 |

列表每頁 20 筆並提供分頁。

## 2. 新增員工

新增員工採單頁輸入，不分步驟，一次建立員工、任職、組織關係、登入帳號及角色。

### 2.1 基本資料

| 欄位 | 必填性 | 規則 |
|---|---|---|
| 員工編號 | 必填 | 由建立者人工輸入 |
| 姓名 | 必填 | — |
| 性別 | 必填 | — |
| 身分證字號 | 必填 | 敏感資料 |
| 出生日期 | 必填 | 敏感資料 |
| 手機 | 必填 | 敏感資料 |
| Email | 選填 | 敏感資料 |
| 地址 | 必填 | 敏感資料 |

### 2.2 任職與組織

| 欄位 | 必填性 | 規則 |
|---|---|---|
| 僱用類型 | 必填 | 正職、兼職、約聘等 |
| 任職性質 | 選填 | — |
| 到職日期 | 必填 | — |
| 部門 | 必填 | 從組織架構選擇 |
| 職稱 | 依公司設定 | 從職稱主檔選擇 |
| 職務 | 依公司設定 | 可指派多個職務 |

### 2.3 眷屬、扣繳與勞退

- 新增時可以一併新增扶養眷屬，也可以建立員工後補登。
- 眷屬資料包含姓名、身分證字號、出生日期及關係。
- 眷屬身分證字號必填，列表顯示時遮罩。
- 薪資扣繳方式必填。
- 可以設定勞退自願提繳率。

### 2.4 登入帳號與角色

- 新增員工時一定建立登入帳號。
- 初始密碼由建立者輸入。
- 員工第一次登入必須強制變更密碼。
- 建立帳號時至少指派一個角色。
- 一個員工可以同時擁有多個角色。
- 員工、任職、帳號及角色應一次建立；任一失敗時整筆取消。

## 3. 修改員工

修改採分頁呈現，每個分頁獨立儲存。

### 3.1 基本資料

可修改員工編號、姓名、性別、身分證字號、出生日期、手機、Email及地址。

員工編號可以修改，但新編號不得與同公司其他員工重複，且需保留異動紀錄。

### 3.2 任職資料

可查看及維護僱用類型、任職性質、到職日期、任職狀態與歷次任職期間。

辦理離職時必填：

- 離職日
- 最後工作日
- 離職原因

離職完成後：

- 本次任職狀態改為離職。
- 登入帳號同步停用。
- 不刪除帳號、角色、人事資料或歷史紀錄。
- 日後回任時新增任職紀錄，不覆蓋舊任職。

### 3.3 組織資料

可以修改部門、職稱及一個或多個職務。

- 組織異動必須指定未來生效日。
- 生效日前仍顯示目前組織資料。
- 生效後才切換到新部門、職稱或職務。
- 所有異動保留前後內容與有效期間。
- 同一時間只能有一個有效部門及一個有效職稱。
- 同一時間可以有多個有效職務。

### 3.4 眷屬與扣繳

可以新增、修改及終止扶養眷屬，列表顯示姓名、遮罩身分證字號、關係及扶養期間。

同頁維護：

- 薪資扣繳方式及生效日
- 勞退自願提繳率及生效日

設定變更均保留歷史及有效期間。

### 3.5 帳號與角色

可以管理登入帳號狀態、直接重新設定密碼、增加角色及移除角色。

- 管理者直接輸入員工的新密碼。
- 不發送 Email、簡訊或系統通知。
- 不保存明碼密碼。
- 每個公司帳號至少保留一個有效角色。
- 系統禁止移除最後一個角色。
- 角色指派與撤銷保留時間及操作者。

### 3.6 薪資設定

可管理：

- 員工薪資項目
- 金額或計算基礎值
- 生效日期
- 薪轉銀行
- 薪轉帳號

薪資項目與銀行帳戶異動均保留歷史，不直接覆蓋已生效舊資料。銀行帳號在一般畫面遮罩顯示。

### 3.7 歷史紀錄

依時間顯示員工建立、員工編號與基本資料修改、任職異動、組織異動、眷屬異動、扣繳及勞退設定異動、帳號與角色操作、薪資設定與銀行帳戶異動及離職。

歷史紀錄需顯示異動時間、異動者、異動類型、異動前後內容，以及適用時的生效日或有效期間。敏感資料不得以明文出現在歷史內容中。

## 4. 已確認規則摘要

1. 新增員工採單頁，修改員工採分頁。
2. 員工編號人工輸入且可修改。
3. 新增員工一定建立帳號並至少指派一個角色。
4. 初始密碼由建立者設定，首次登入強制修改。
5. 管理者重設密碼不發送通知。
6. 員工至少保留一個角色。
7. Email與任職性質選填；薪資扣繳方式必填。
8. 眷屬身分證字號必填。
9. 組織異動必須指定未來生效日。
10. 辦理離職必填離職日、最後工作日與離職原因，並同步停用帳號。
