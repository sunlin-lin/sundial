# UI 與流程設計：我的資料／加班申請

## 確認狀態

本文件內容已由使用者明確同意，列為正式 UI、流程與資料責任規劃。

## 導覽與查詢

```text
我的資料
├─ 個資
├─ 出勤紀錄
├─ 補打卡申請
├─ 請假與餘額
└─ 加班申請
```

本頁只能處理目前登入員工本人的加班申請。年月預設當月，可依狀態查詢全部、待審核、已核准、未核准、已撤回及已取消。

## 申請列表

| 日期 | 時段 | 日別 | 出勤 | 計酬 | 加班費 | 事由 | 狀態 | 操作 |
|---|---|---|---|---|---:|---|---|---|

- 日期依班表工作日期歸屬。
- 出勤顯示申請所依據的有效上下班時間。
- 計酬為加班費或補休。
- 加班費待審核時可顯示試算，核准後顯示正式認列金額；補休顯示「—」。
- 操作提供查看；待審核時可由申請人撤銷申請。
- 日期預設由新到舊。

## 必要條件

- 必須同時有有效上班卡與下班卡，並能形成完整有效出勤區間。
- 只有單一卡、缺卡或無法配對時不可申請。
- 已撤銷打卡不可作為依據。
- 補打卡尚未核准時不可申請；核准形成正式打卡後才可。
- 跨日班只要上下班正確配對即屬完整出勤。
- 多次進出須先形成有效配對區間。
- 送出及審核時都需重新檢查打卡仍有效。
- 因須先有完整打卡，不接受未來日期預先申請。
- 已結算月份不得新增加班申請。

## 可申請區間

```text
可申請加班區間
＝完整有效出勤區間
－當日班表正常工作時段
```

- 系統只提供候選區間，不自動把所有區間申報為加班。
- 工作日扣除正常工作時段；正常班表內休息時間不自動算加班。
- 休息日或國定假日若無正常時段，可依有效出勤產生候選區間。
- 例假日依公司及法規規則判定是否可申請。
- 申請時段不得超出有效出勤、不得與正常工作時段重疊，也不得被其他有效申請重複使用。
- 實際打卡超過申請區間不自動增加認列時數。
- 跨日班以班表工作日期歸屬。
- 最小單位、進位與倍率依公司及法規規則。

## 新增申請

| 欄位 | 必填性 | 說明 |
|---|---|---|
| 加班日期 | 必填 | 只能選有完整有效打卡的日期 |
| 日別 | 系統顯示 | 依班表與規則判定 |
| 當日班表 | 系統顯示 | 正常工作及休息時段 |
| 當日出勤 | 系統顯示 | 有效上下班時間 |
| 可申請時段 | 系統計算 | 有效出勤扣除正常班表 |
| 加班開始時間 | 必填 | 位於可申請區間 |
| 加班結束時間 | 必填 | 位於可申請區間 |
| 申請時數 | 系統計算 | 由起訖換算 |
| 計酬方式 | 必填 | 加班費或補休；一筆不可拆分 |
| 加班費試算 | 條件顯示 | 選擇加班費時顯示 |
| 事由 | 必填 | 加班原因 |

## 待審核撤銷

- 員工自己提出且尚未審核的申請，可以自行撤銷。
- 只有待審核狀態、且申請人為本人時可操作。
- 撤銷前顯示日期、時段及計酬方式並再次確認。
- UI 操作名稱可為「撤銷申請」，流程狀態保存為「已撤回」。
- 撤回時間及歷史必須保留，不得 DELETE。
- 已撤回申請不再審核，也不產生加班費或補休。
- 已核准、未核准及已取消申請不可使用此操作。
- 再次申請須建立新申請，不恢復舊申請。

## 打卡撤銷關係

- 打卡被待審核加班申請引用時，需先撤回加班申請，才能撤銷打卡。
- 已核准加班所依打卡不得由員工直接撤銷。
- 修正已核准加班的打卡時，需先處理核准與已產生補償。
- 所有原始打卡、申請及審核歷史必須保留。

## 核准後

```text
完整有效打卡
→ overtime_requests
→ overtime_approvals
→ overtime_compensations
→ 加班費或 compensatory_leave_credits
```

- 加班費依日別、法規、公司規則及薪資基準計算並進入薪資結算。
- 補休於核准後逐筆建立額度，並可追溯至加班申請。
- 申請不得修改原始打卡或班表。
