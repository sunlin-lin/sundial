# UI 設計規劃：我的資料／個資

## 確認狀態

本文件內容已由使用者明確同意，列為正式 UI 規劃。

## 導覽結構

```text
我的資料
└─ 個資
```

## 頁面配置

「個資」使用同一入口，分為兩個頁籤：

```text
個人資料｜變更密碼
```

## 個人資料

個人資料只能查看，不提供編輯及儲存操作。

| 顯示內容                                                        | 資料責任                                     |
| --------------------------------------------------------------- | -------------------------------------------- |
| 員工編號、姓名、性別、身分證件資料、出生日期、手機、Email、地址 | `employees`                                  |
| 到職日期、任職狀態、僱用類型                                    | 目前有效的 `employee_employments`            |
| 所屬部門                                                        | 目前有效的 `employee_department_histories`   |
| 職稱                                                            | 目前有效的 `employee_job_title_histories`    |
| 職務                                                            | 目前有效的 `employee_job_position_histories` |

### 存取規則

- 只能讀取目前登入帳號在目前公司所連結的本人員工資料。
- 個資頁所有人事欄位唯讀，不顯示編輯或儲存按鈕。
- 部門、職稱及職務顯示目前有效紀錄。
- 資料有誤時不在本頁直接修改，可提示聯絡人事。
- 敏感資料是否遮蔽及遮蔽規則尚未定案。

## 變更密碼

| UI 欄位    | 必填性 | 規則                       |
| ---------- | ------ | -------------------------- |
| 目前密碼   | 必填   | 驗證目前登入者             |
| 新密碼     | 必填   | 必須符合後續定義的密碼規則 |
| 確認新密碼 | 必填   | 必須與新密碼一致           |

### 安全與資料責任

- 密碼變更作用於登入帳號 `users`，不得寫入 `employees`。
- 不顯示、傳回或保存原始目前密碼。
- 新密碼以單向雜湊保存，不得保存明文或可解密密碼。
- 新密碼不得與目前密碼相同。
- 變更成功後需要保存密碼變更時間；正式欄位名稱與型態待 `users` 逐欄確認。
- 密碼複雜度、歷史密碼限制、失敗次數限制及是否登出其他裝置尚未定案。

## Schema 狀態

本輪確認 UI、存取規則及資料責任，不代表 `users` 與 `company_users` 的全部欄位已完成確認：

- `users`：已確認存在；完整欄位待逐欄確認。
- `company_users`：已確認存在；需負責目前公司成員與本人員工資料的連結，完整欄位待逐欄確認。
- 不建立「個資頁專用資料表」；畫面讀取既有帳號、人事及歷史資料。
