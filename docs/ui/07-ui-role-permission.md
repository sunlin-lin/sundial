# UI 設計規劃：角色與權限

## 導覽結構

```text
系統設定
└─ 權限／角色
```

進入頁面後採左右雙欄：左側為角色清單，右側為所選角色的基本資料與權限樹。UI 不顯示「系統預設／公司自訂」分類；`roles.is_system` 僅供後端管理保護規則使用。

## 畫面配置

### 左側角色清單

- 顯示所有目前可用角色。
- 點選角色後，右側立即載入該角色資料與權限。
- 頁面提供「新增角色」。
- 不在角色名稱旁標示預設或自訂。

### 右側角色資料

| UI 欄位／操作 | Schema 對應                       | 規則                               |
| ------------- | --------------------------------- | ---------------------------------- |
| 角色名稱      | `roles.name`                      | 必填                               |
| 角色代碼      | `roles.code`                      | 公司內唯一；建立後原則上不任意修改 |
| 說明          | `roles.description`               | 選填                               |
| 啟用狀態      | `roles.status`                    | 停用後不可再授予                   |
| 權限樹        | `permissions`、`role_permissions` | 大權限與小權限階層顯示             |
| 儲存變更      | `roles`、`role_permissions`       | 角色與權限應在同一交易完成         |
| 刪除角色      | `roles.deleted_at`                | 採 Soft Delete，不直接刪除歷史     |

## 權限樹

權限使用 `permissions.parent_id` 建立大權限／小權限：

```text
員工管理
├─ 查看員工
├─ 新增員工
├─ 修改員工
└─ 查看敏感個資
```

### 勾選行為

- 勾選大權限：勾選其全部小權限。
- 取消大權限：取消其全部小權限。
- 只勾選部分小權限：大權限顯示半選狀態。
- 大權限負責分類與批次選取；實際授權以可授權的小權限為主。
- 儲存時，選取的小權限建立 `role_permissions`；取消選取者解除有效關聯。

## 新增角色

1. 點擊「新增角色」。
2. 左側產生尚未儲存的角色草稿。
3. 右側輸入角色名稱、代碼、說明及狀態。
4. 選擇小權限。
5. 儲存角色與權限關聯。

若任何步驟失敗，整次操作必須回滾，不能留下缺少預期權限的半成品角色。

## 刪除角色

刪除採 `roles.deleted_at` Soft Delete，與目前 `roles` Schema 相容。

刪除前必須檢查：

- 角色是否仍授予任何公司成員／登入帳號。
- 是否為公司最後一個具管理能力的角色。
- 是否已有待處理的角色移轉。

處理規則：

- 未被使用的角色可直接標記刪除。
- 已被使用的角色不能直接刪除，必須先將使用者移轉至其他角色。
- 公司最後一個管理角色不得刪除。
- 已刪除角色不得再授予新使用者。
- 歷史操作紀錄仍須能顯示當時使用的角色。
- `role_permissions` 不應因角色 Soft Delete 而物理刪除；查詢有效權限時排除已刪除角色。

## 由 UI 發現的 Schema 缺口

### `permissions` 建議補充

| 欄位            | 型態      | 用途                             | 狀態                 |
| --------------- | --------- | -------------------------------- | -------------------- |
| `is_assignable` | `boolean` | 區分純分類大權限與可實際授權權限 | UI 規劃待納入 Schema |
| `sort_order`    | `integer` | 控制大權限及小權限顯示順序       | UI 規劃待納入 Schema |

### 帳號／公司成員與角色關聯

目前與帳號相關的確認狀態：

```text
users              已確認採用；欄位待逐欄確認
company_users      已確認採用；欄位待逐欄確認
company_user_roles 尚未定案
```

`users` 與 `company_users` 的表名、用途及責任邊界已由使用者確認，但目前仍無法表示「哪個公司成員擁有哪些角色」。角色關聯暫稱 `company_user_roles`，其正式表名與欄位仍須另外確認，不得因前兩表定案而連帶視為已確認 Schema。

至少必須支援：

- 一個公司成員可有一個或多個角色。
- 每筆授予可追蹤授予者及授予時間。
- 角色 Soft Delete 前可查出仍被授予的成員。
- 同一角色不得重複授予同一公司成員。
- 公司成員、角色及公司必須屬於同一 Tenant。

## 與目前 Schema 的相容性結論

- 左側角色清單、建立與編輯：與 `roles` 相容。
- 大／小權限樹：與 `permissions.parent_id` 相容。
- 角色勾選權限：與 `role_permissions` 相容。
- 不顯示預設／自訂：不影響後端保留 `roles.is_system`。
- 刪除角色：與 `roles.deleted_at` 相容，採 Soft Delete。
- 刪除前判斷角色是否被使用：目前缺少帳號／公司成員角色關聯，須在帳號模型階段補足。
