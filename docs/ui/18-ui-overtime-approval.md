# UI 與流程設計：簽核／加班簽核

## 確認狀態

本文件內容已由使用者明確同意，列為正式 UI、流程與 Schema 規劃。

## 導覽與權限

```text
簽核
├─ 補打卡簽核
└─ 加班簽核
```

只有具備加班審核權限的角色可查看及操作。

## 預設查詢與分頁

- 進入頁面預設顯示待審核，立即載入第 1 頁。
- 每頁固定 20 筆，待審核依申請時間由舊到新。
- 年月預設當月，以加班工作日期查詢。
- 可依狀態、部門、人員、計酬方式及日別篩選。
- 條件改變回到第 1 頁；查詢、排序及分頁由後端處理。

## 列表

| 申請日期 | 員工 | 部門 | 加班日期 | 日別 | 申請時段 | 有效出勤 | 申請時數 | 計酬 | 事由 | 狀態 | 操作 |
|---|---|---|---|---|---|---|---:|---|---|---|---|

部門使用加班日期當時有效部門。第一版逐筆審核，不提供批次核准。

## 審核明細與可認列區間

顯示申請資料、當日班表、休息時段、完整有效打卡、撤銷／補登來源及大約地址。

```text
可認列加班區間
＝完整有效出勤區間
－正常班表工作時段
－已被其他有效加班申請使用的區間
```

## 不允許修改申請時間

- 審核者不能修改、縮短、延長或移動員工申請時段。
- 不允許部分核准。
- 不新增 `recognized_start_at` 或 `recognized_end_at`。
- 只能整筆核准或整筆退回。
- 核准時 `overtime_compensations.recognized_minutes = overtime_requests.requested_minutes`。
- 只有部分符合時整筆退回；員工需建立新申請。

## 核准與退回

核准前重新檢查申請待審核、員工未撤回、上下班卡仍完整有效、申請時段完整位於可認列區間、沒有重疊且薪資尚未核算。

核准後新增 `overtime_approvals`、建立有效 `overtime_compensations`；加班費進入薪資，補休則建立 `compensatory_leave_credits` 與換算快照。

退回原因必填；保留歷程，不產生補償。員工待審核時可自行撤回。

## 撤銷審核結果

薪資尚未開始核算時：

### 撤銷核准

- 撤銷原因必填。
- 原核准及補償保留，不得 DELETE。
- 將有效 `overtime_compensations` 標記撤銷。
- 加班費尚未進入薪資核算時可撤銷。
- 補休尚未使用時，先撤銷補休額度，再撤銷加班核准。
- 補休已被使用時，不可直接撤銷核准。
- 完成後申請回到待審核。

### 撤銷退回

- 撤銷原因必填。
- 原退回歷程保留。
- 申請回到待審核，可重新審核。

### 禁止撤銷

- 薪資已開始核算。
- 加班費已進入薪資處理。
- 補休已被使用。
- 相關資料已進入不可變更結算。

## 審核歷程動作

`overtime_approvals.action_code`：

1. 核准
2. 退回
3. 撤銷核准
4. 撤銷退回
5. 取消

歷程只能新增，不得覆寫或刪除。退回、撤銷核准及撤銷退回時原因必填。

## 併發與薪資限制

- 薪資開始核算後只可查看，不可改變審核結果。
- 薪資核算前，待審核申請應先完成審核或由員工撤回。
- 多人同時操作時第一筆成功生效，後送操作須拒絕並重載最新狀態。
