# UI 設計規劃：我的資料／出勤紀錄

## 確認狀態

本文件內容已由使用者明確同意，列為正式 UI 規劃。

## 導覽結構

```text
我的資料
├─ 個資
└─ 出勤紀錄
```

本頁只能查看目前登入員工本人的出勤資料，不得查看其他員工。

## 頁面順序

```text
年月查詢
↓
當月出勤統計
↓
出勤紀錄列表
```

## 年月查詢

- 進入頁面時預設為系統當月。
- 進入後立即載入當月統計與列表，不需再次點擊查詢。
- 可切換其他年份及月份。
- 切換年月後重新載入該月統計與明細。
- 不提供部門或人員選擇，因本頁固定只查本人。

## 當月出勤統計

顯示：

```text
出勤 22 天
總工時 170.1 小時
遲到 1 天
早退 1 天
缺勤 0 天
```

| 統計項目 | 計算規則 |
|---|---|
| 出勤天數 | 當月有有效出勤紀錄的工作日數；同一天只計一次 |
| 總工時 | 加總 `attendance_results.worked_minutes`，由分鐘換算為小時，顯示至小數一位 |
| 遲到天數 | `late_minutes > 0` 的工作日數 |
| 早退天數 | `early_leave_minutes > 0` 的工作日數 |
| 缺勤天數 | `absence_minutes > 0` 的工作日數 |

- 同一天同時遲到及早退時，兩項各計一天。
- 已撤銷打卡不納入統計。
- 出勤重新計算後，統計與列表必須同步更新。

## 出勤紀錄列表

| 日期 | 上班 | 上班地點 | 下班 | 下班地點 | 工時 | 遲到 | 早退 | 狀態 | 來源 |
|---|---|---|---|---|---|---|---|---|---|

### 顯示規則

- 一個工作日一列。
- 日期預設由新到舊排列。
- 跨日班歸屬於班表的工作日期，不依下班的日曆日期拆成兩列。
- 上班及下班顯示出勤判定採用的有效打卡。
- 上下班地點顯示 GPS 反查後的大約地址；主列表不直接顯示經緯度。
- 沒有 GPS 或無法反查地址時顯示「—」。
- 遲到或早退為零時顯示「—」。
- 工時由分鐘轉換為使用者容易閱讀的時數格式。
- 同一天可以同時顯示多個出勤狀態。
- 尚未完成出勤計算時顯示「計算中」。
- 一個月最多約 31 列，預設不分頁。

## 明細查看

點選任一日期可查看：

- 今日班別及預定時間。
- 系統採用的上下班卡。
- 當日全部原始打卡。
- 已撤銷打卡及撤銷原因。
- 上下班大約地址。
- 工時、遲到、早退及缺勤計算結果。
- 打卡、補登、請假或系統判定等資料來源。

明細目前只能查看；是否允許從此處申請補卡或更正尚未定案。

## 資料來源

- 工時、遲到、早退、缺勤及出勤狀態：`attendance_results`。
- 上下班時間、來源及位置：正式打卡事件。
- 員工身分：登入帳號 `users` 經目前公司的 `company_users` 找到本人所連結的 `employee_id`。
- 本頁不建立新的出勤統計資料表；統計由該月有效出勤結果彙總。

## 權限與安全

- 後端必須依登入身分決定員工，不接受前端任意指定其他 `employee_id`。
- 使用者切換公司後，只能讀取該公司成員關係連結的本人資料。
- 已撤銷打卡可在明細查看，但不參與有效出勤與統計。
- 已鎖定的出勤歷史不得因後續重算而無痕改寫。
